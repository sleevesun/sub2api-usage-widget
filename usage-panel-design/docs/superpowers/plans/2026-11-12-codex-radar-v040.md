# Codex Radar v0.4.0 implementation

Approved goal: integrate the in-app prototype into the existing usage widget, add a TPS column, deliver a portable Windows x64 EXE, and publish a signed stable GitHub Release compatible with v0.3.0.

## Constraints

- Both radar views include only GPT-6 and GPT-6.1 families, dynamically discovered from the official homepage's `home-overview-data` JSON, `scores.rows`.
- Matrix is the default. Efforts: ultra, max, xhigh, high, medium, low, then other efforts alphabetically. Model versions descend; equal versions sort by best score descending.
- Rank each model/effort separately. Score, score/USD and score/minute each show at most five. Ranking-only strict raw score > 90 filter defaults on and is shared with the expanded view.
- Bench max is 150; explain that “智商” is not human IQ. Distinguish unknown/ungraded from explicitly unsupported tiers. Keep cost_kind and available round metadata; show test completion in Asia/Shanghai.
- Cache complete snapshots in memory for ten minutes. Manual refresh bypasses cache; failed refresh retains one complete previous snapshot. No cross-round merging. Coalesce concurrent requests; ignore obsolete responses.
- Follow existing light/dark theme and in-app placement. Narrow tables scroll internally; rankings stack.
- Model consumption still includes all usage models. Add nullable tps after Token; the live service has no per-model timing/TPS, so show — with “接口未提供模型 TPS”. Do not infer TPS from total tokens or global duration.
- v0.4.0 retains app identifier, updater key, endpoint and credential locations. Portable EXE and signed installer/update manifest come from the same build.
